# Domain Map

- Academic records: courses, credits, grades, GPA, RPL, retakes.
- Graduation and scholarships: criteria vary by entry year and department.
- Timetable: conflict detection, custom start times, alarms, permission state.

시간표 탭은 연도·학기별 개설 강의를 조회하고 학생 본인의 시간표에
등록·변경·삭제합니다. 같은 학기의 다른 강의로만 변경하며 시간 충돌은
서버가 판정합니다. 수업은 학교 현지 시간으로 표시하며 월~토 6열을
항상 화면 너비 안에 표시합니다. 일요일 수업이 있으면 일요일도 함께 표시합니다.
강의 블록을 누르면 전체 과목명·교수·시간·강의실을 확인합니다.
계정 변경 시 시간표와 진행 중 요청을 초기화합니다.
개인 시간 변경과 기기 알림은 후속 범위입니다.
- Recommendations: 시간표 탭에서 고른 정규학기(1·2학기)의 수강 추천을 엽니다.
  서버가 졸업 필수 미이수 → 권장 학기 지남 → 이번 학기 권장 → 재수강(C+ 이하·F·NP)
  순서로 정렬해 주고, 앱은 전공별로 이유와 개설 분반을 표시만 합니다. 계절학기에는
  버튼을 끄고, 개설 정보가 없는 학기와 교과과정이 공개되지 않은 전공을 안내합니다.
  선수과목과 교수 선호도는 후속 범위입니다.
- Notices and inquiries: authenticated student scope and notification state.

Pure domain rules must not import Flutter widgets or platform plugins.

성적 등록은 수강연도와 학기별 개설 강의에서 중복 과목을 제거하여 검색합니다. 연도 또는 학기를 바꾸면 과목·자동 학점·재수강 선택과 검색을 초기화하고 이전 요청의 늦은 응답은 무시합니다. 해당 학기 개설 자료가 없으면 과목을 선택할 수 없습니다. 기존 성적의 연도와 학기를 유지한 수정은 개설 자료가 없어도 허용합니다.

평점 시뮬레이션은 `성적` 화면의 계산기 버튼에서 시작합니다. 과목 분류·학점·예상 등급을 입력하고 `POST /api/v1/grades/simulation`이 반환한 현재·예상 GPA와 이수학점을 비교합니다. 화면에서는 GPA를 자체 계산하지 않습니다.

예상 과목은 최대 50건이며 실제 성적이나 기기에 저장하지 않습니다. 입력 변경, 화면 종료, 학생 계정 변경 시 결과를 초기화합니다. 실패 시 입력을 유지하여 다시 계산할 수 있고, 인증 만료 시 로그인으로 돌아갑니다. 예상 재수강/RPL과 목표 평점 역산은 이번 범위에 포함하지 않습니다.

단위·위젯·호스트 통합 테스트는 `./scripts/verify`로 검증합니다. 기기 확인은 로그인 → 성적 → 평점 시뮬레이션 → 예상 성적 입력 → 계산 → 입력 수정 후 재계산 순서로 진행합니다. 실제 성적 목록이 바뀌지 않는지도 확인합니다.

장학요건은 `성적` 화면의 장학요건 버튼에서 엽니다. `GET /api/v1/scholarship-eligibility`가 주전공 학과·입학연도 기준으로 계산한 누적 평점, 이수학점, 학사경고 횟수(정규학기 평점 1.70 미만)와 장학금별 충족 여부·부족분을 그대로 보여 주며, 화면에서 직접 판정하지 않습니다. 등록된 기준이 없으면 빈 목록으로 오고, 문의사항으로 관리자에게 알리도록 안내합니다. 학생 계정이 바뀌면 결과를 초기화하고, 인증 만료 시 로그인으로 돌아갑니다. 결과는 안내용이며 실제 장학 선발 결과가 아닙니다.

문의 첨부파일은 문의 상세 화면에서 관리합니다. 답변 전(접수됨·확인 중) 문의에만 `사진 첨부`(시스템 사진 선택기)와 `PDF 첨부`(파일 앱)로 JPG·PNG·PDF를 5MB 이하, 문의당 3개까지 올리고 삭제할 수 있습니다. 답변된 문의는 목록만 보여 줍니다. 확장자와 크기는 업로드 전에 확인하고 HEIC처럼 지원하지 않는 형식은 안내 문구로 거절합니다. 사진은 기기에서 위치 정보를 포함한 메타데이터를 지운 뒤 올립니다. 이때 카메라 사진의 회전 정보도 함께 지워져 옆으로 보일 수 있습니다. 앱 안에서 첨부파일을 열어 보는 기능은 이번 범위에 없습니다.

성적 등록에서 5MB 이하 PDF(최대 5쪽)를 선택하면 Android/iOS 기기에서 페이지를 이미지로 변환한 뒤 한국어 OCR 결과를 미리 볼 수 있습니다. 과목명은 DB에서 연결된 이름을 우선 표시하고, 카탈로그에서 매칭되지 않으면 OCR로 읽은 과목명을 표시합니다. 과목별 학점·성적을 확인하거나 수정한 후 체크한 항목만 `선택한 N개 등록` 버튼으로 저장합니다. `course` 전체 활성 카탈로그를 한 번 받아 학수번호로 대조하며, 한 글자 다른 과목은 사용자가 과목 수정 화면에서 직접 고릅니다. 과목명 유사도는 사용하지 않습니다. 기존 성적과 PDF 내 동일 과목·학기 중복은 등록 대상에서 제외합니다. 수강연도·학기는 성적표의 값을 보내되, 서버는 해당 연도·학기의 `lecture` 개설 여부를 검증합니다. 현재 앱의 과목 조회는 `course`, 서버 등록 검증은 `lecture` 기준이며 과거 학기의 개설 강의가 없으면 저장이 거절됩니다. 이 기준 통합은 후속 작업입니다. 카탈로그에서 과목을 찾지 못하면 확인 후 직접 과목을 선택해야 합니다. 저장은 기존 성적 API에 항목별로 요청하고, 일부 실패 시 성공한 항목을 유지하며 재시도 전 기존 성적을 다시 확인합니다. 완료 후 성적 목록을 새로고침합니다. 전체 인식 텍스트 영역은 표시하지 않으며 과목별 인식 텍스트만 펼쳐 확인할 수 있습니다. 학점인정·재수강 대체 성적은 기존 수동 등록 화면에서 처리합니다. iOS는 Apple Vision, Android는 ML Kit으로 기기에서 인식합니다.

OCR은 학수번호의 세로 위치로 과목 행을 나누고, 표의 `학점`·`평점` 머리글 위치 안에서만 값을 읽습니다. iOS에서는 좌우 표를 별도로 인식한 뒤 학점·평점 열을 영문·숫자 인식으로 다시 확인합니다. 1차와 재인식 값이 충돌하거나 여러 값이 잡히면 해당 항목을 비우고 `확인 필요`로 표시합니다. OCR이 제시한 다른 인식 후보는 성적 형식에 맞는 경우에만 활용하며, `At` 같은 문자열을 임의로 `A+`로 치환하지 않습니다. `1TC`처럼 혼동된 학수번호도 원문을 보존해 DB 후보 선택에 사용합니다. 현재 검증한 양식은 좌우 두 칸의 인하대 성적표이며, 다른 양식의 정확도는 보장하지 않습니다.
